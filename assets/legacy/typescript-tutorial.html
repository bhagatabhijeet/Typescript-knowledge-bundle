Typed, From Scratch

TypeScript is JavaScript that tells you when you're about to break something — before your code ever runs. This course walks you from your first string to your first generic, one small idea at a time.

Start Chapter 1 → No install required — every example fits in the TypeScript Playground.
greet.js
greet.ts
function greet(user: { name: string }) {
  return `Hello, ${user.name.toUpperCase()}!`;
}

greet({ nme: "Ada" });
Error: Argument of type '{ nme: string }' is not assignable to parameter of type '{ name: string }'. Object literal may only specify known properties, but 'nme' does not exist in type '{ name: string }'. Did you mean to write 'name'?

The plain JavaScript version of this bug would run fine — right up until user.name.toUpperCase() crashes on undefined. TypeScript catches the typo while you're still writing the call.

Chapter 1 · Concept

What is TypeScript, really?

A type-checker that sits in front of JavaScript, then gets out of the way.

TypeScript is JavaScript plus a layer of type annotations — extra syntax that describes the shape of your data (this is a string, that function returns a boolean, this object always has a name). A tool called the compiler (tsc) reads those annotations, checks that your code is internally consistent, and then erases them, leaving plain JavaScript behind.

That last part matters: types are a design-time tool, not a runtime one. They cost you nothing when the code actually runs — the browser or Node.js never sees a single : string. They exist purely so mistakes surface on your screen, in your editor, seconds after you make them, instead of in front of a user weeks later.

Why bother?

  • Typos become errors. Misspell a property name and TypeScript flags it immediately, the way the hero example above does.
  • Refactors get safer. Rename a field and every place that used the old name lights up red until you fix it.
  • Your editor gets smarter. Autocomplete, inline docs, and "go to definition" all work far better once the editor knows what shape your data actually is.

Tip

You are never fighting JavaScript when you write TypeScript — every valid JavaScript file is already almost valid TypeScript. You're only ever adding information, never a different language.

Chapter 2 · Guide

Get it running

Two ways to try TypeScript: zero-install, or a real project.

Option A — the Playground

The fastest way to follow along with this course is the official TypeScript Playground: paste code in, see the compiled JavaScript and any errors on the right, instantly. Nothing to install.

Option B — a real project

When you're ready to add TypeScript to actual code, install it as a project dependency and let it generate a config file:

terminal
npm install --save-dev typescript
npx tsc --init
npx tsc greet.ts

The first line installs the compiler locally. The second generates a tsconfig.json — the file that controls how strict the checker is (more on that in the reference bundle this course belongs to). The third compiles greet.ts into plain greet.js, ready to run anywhere JavaScript runs.

Tip

Every code example from here on is short enough to paste straight into the Playground — you don't need a local project to finish this course.

Chapter 3 · Concept

The basic types

The building blocks you'll reach for in nearly every file.

You can annotate a variable explicitly with a colon, but TypeScript is usually smart enough to infer the type from the value you assign — you'll only write annotations by hand where there's nothing to infer from yet, like an empty parameter.

basics.ts
let city: string = "Austin";   // explicit annotation
let age = 29;                  // inferred as number
let isActive = true;           // inferred as boolean

let tags: string[] = ["css", "html", "ts"];
let coordinate: [number, number] = [30.27, -97.74]; // a tuple: fixed length & order

An array type (string[]) can grow or shrink and every item must match. A tuple ([number, number]) is a fixed-length array where each position has its own type — useful for things like coordinates or a [key, value] pair.

Common mistake

Once TypeScript infers a type for let, it holds you to it:

basics.ts
let city = "Austin";
city = 42;
Error: Type 'number' is not assignable to type 'string'.

The four special-purpose types

TypeMeans
anyTurns checking off for that value. Escape hatch — avoid it when you can.
unknownThe safe any: you must narrow it (check its type) before you're allowed to use it.
voidA function that doesn't return a meaningful value.
neverA function that never finishes normally — it always throws or loops forever.

Given let count = 10; with no annotation written, what type does TypeScript infer for count?

Right — TypeScript looks at the literal 10 and infers number, exactly as if you'd written let count: number = 10; yourself.

Chapter 4 · Concept

Shaping objects: interfaces & type aliases

Give a recurring shape a name, once.

Most real data is an object, not a single value. You describe its shape with an interface or a type alias — for plain object shapes the two are nearly interchangeable:

user.ts
interface User {
  id: number;
  name: string;
  email?: string;        // the ? means optional
  readonly createdAt: Date; // set once, never reassigned
}

const ada: User = {
  id: 1,
  name: "Ada Lovelace",
  createdAt: new Date(),
};

email is optional, so leaving it out above is fine — but id, name, and createdAt are required. Mark a property readonly when it should be set once and never reassigned.

"If it walks like a User…"

TypeScript uses structural typing: a value satisfies User if it has the right shape, whether or not it was ever declared as one. There's no implements User needed on a plain object — only classes use implements explicitly, which you'll see in Chapter 8.

Tip

Reach for interface when you're describing an object or a class shape, and type when you need a union ("pending" | "done") or anything that isn't a plain object — a habit that will serve you well as your types grow up.

Chapter 5 · Concept

Functions

Typing the inputs is where TypeScript earns its keep.

pricing.ts
function formatPrice(cents: number, currency: string = "USD"): string {
  return `${(cents / 100).toFixed(2)} ${currency}`;
}

const shout = (message: string): void => {
  console.log(message.toUpperCase());
};

function findUser(id: number, cache?: Map<number, User>) {
  // cache is optional: `Map<number, User> | undefined`
}

Parameters are typed the same way variables are. currency: string = "USD" is a default parameter — skip it and TypeScript fills it in. cache? is an optional parameter — its type quietly becomes Map<number, User> | undefined. The : string and : void after the parameter list annotate the return type, though TypeScript can usually infer that too.

Common mistake

Required parameters can't come after optional or default ones — TypeScript won't know which argument you meant to skip:

pricing.ts
function formatPrice(currency: string = "USD", cents: number) {}
Error: A required parameter cannot follow an optional parameter.

Chapter 6 · Concept

Union types, literals & narrowing

"One of these" is a type too.

A union (|) says a value can be one of several types. A literal type narrows that further to one exact value:

status.ts
let id: string | number;
id = "sku-42";   // fine
id = 42;         // also fine

type RequestStatus = "idle" | "loading" | "success" | "error";

function describe(status: RequestStatus) {
  if (status === "loading") return "Hang tight…";
  return `Status: ${status}`;
}

RequestStatus can now only be one of those four strings — pass anything else and TypeScript rejects it before the code ever runs.

Narrowing

Once a value's type is a union, TypeScript won't let you use members that don't exist on every branch until you narrow it — prove, with an ordinary JavaScript check, which branch you're in:

narrow.ts
function printId(id: string | number) {
  if (typeof id === "string") {
    console.log(id.toUpperCase()); // TypeScript knows id is a string here
  } else {
    console.log(id.toFixed(2));    // and a number here
  }
}

Inside the if (typeof id === "string") branch above, what does TypeScript treat id as?

Right — the typeof check narrows the union down to just string for the rest of that branch, so .toUpperCase() is safe to call.

Chapter 7 · Concept

Enums

A named set of related constants.

direction.ts
enum Direction {
  Up,
  Down,
  Left,
  Right,
}

function move(dir: Direction) { /* ... */ }
move(Direction.Up);

enum Plan {
  Free = "FREE",
  Pro = "PRO",
}

A plain enum assigns increasing numbers (0, 1, 2…) unless you give string values yourself, as with Plan. Enums are handy for a small, fixed set of related options that show up throughout your code.

Tip

Many teams reach for a string-literal union (type Plan = "FREE" | "PRO", from the last chapter) instead of an enum — it needs no import and behaves like an ordinary string. Both are fine choices; know that you'll see enums in the wild.

Chapter 8 · Concept

Classes

Everything you already know from JavaScript classes, now typed.

account.ts
interface Payable {
  charge(cents: number): void;
}

class Account implements Payable {
  readonly id: number;
  private balanceCents = 0;

  constructor(id: number, public owner: string) {
    this.id = id;
  }

  charge(cents: number): void {
    this.balanceCents -= cents;
  }
}

const acct = new Account(1, "Ada Lovelace");
acct.charge(500);
acct.balanceCents; // Error: 'balanceCents' is private

implements Payable makes TypeScript check that Account really provides everything the interface promises. public owner: string in the constructor is a shortcut that both declares and assigns the property in one line. private hides balanceCents from anything outside the class — readonly means id can be set in the constructor but never again.

Chapter 9 · Concept

Generics, gently

A type that fills itself in at the call site.

Sometimes a function's input and output types are linked, but you don't know the exact type ahead of time — it could be called with a string today and a User tomorrow. A generic (<T>) is a placeholder type that TypeScript fills in from how you actually call the function:

generics.ts
function firstElement<T>(items: T[]): T {
  return items[0];
}

const firstName = firstElement(["Ada", "Grace"]); // T is string, result: string
const firstId = firstElement([1, 2, 3]);          // T is number, result: number

Think of T as a variable, but for types instead of values: <T> declares it, T[] and T use it. Call firstElement with a string[] and every T in the signature becomes string for that call — including the return type, with no casting required.

Tip

You've already been using a generic type: Array<string> (the long form of string[]) and Map<number, User> from Chapter 5 are both generics supplied by TypeScript itself.

Chapter 10 · Reference

Utility types cheat sheet

Built-in helpers that transform a type you already have.

TypeScript ships a handful of generic helpers that reshape an existing type instead of making you redeclare it by hand. Given this base interface:

base.ts
interface User {
  id: number;
  name: string;
  email?: string;
}
UtilityProduces
Partial<User>Every field optional — handy for an "update" payload.
Required<User>Every field required, even email.
Readonly<User>Every field readonly.
Pick<User, "id" | "name">Only id and name.
Omit<User, "email">Everything except email.
Record<string, User>An object type indexed by string keys, e.g. a lookup table by id.
ReturnType<typeof formatPrice>The return type of a function — here, string.

You won't need most of these on day one — bookmark this table and reach for it once you find yourself retyping a shape you already declared elsewhere.

Chapter 11 · Exercises

Practice

Four small problems. Try each one before opening the solution.

1. Add types to this plain JavaScript function

It should take two numbers and return their sum as a string, e.g. addAsString(2, 3) === "5".

exercise-1.ts
function addAsString(a: number, b: number): string {
  return String(a + b);
}
2. Fix the type error

This won't compile — find the mismatch and fix it.

exercise-2.ts
function double(n: number) {
  return n * 2;
}
double("4");
Error: Argument of type 'string' is not assignable to parameter of type 'number'.

Solution — pass a number, not a numeric string:

exercise-2.ts
double(4);
3. Write an interface for this data

Model the shape of a blog post: a numeric id, string title, string body, and an optional publishedAt date.

exercise-3.ts
interface Post {
  id: number;
  title: string;
  body: string;
  publishedAt?: Date;
}
4. Write a generic lastElement function

Same idea as firstElement from Chapter 9, but returning the last item of any array.

exercise-4.ts
function lastElement<T>(items: T[]): T {
  return items[items.length - 1];
}
